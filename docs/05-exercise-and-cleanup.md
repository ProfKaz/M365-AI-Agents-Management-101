# 5. Classroom exercise and cleanup

## Fifteen-minute demonstration

| Minutes | Activity | Learning outcome |
|---|---|---|
| 0–3 | Show agent names and ask learners to group duplicates | Names provide weak evidence |
| 3–6 | Compare instructions from two overlapping recipes | Purpose and sources matter |
| 6–10 | Open the administrative record of a real lab agent | Match creator, ID, sharing and data |
| 10–13 | Fill the review worksheet and choose a correction | Connect a requirement to a decision |
| 13–15 | Explain observed limitations and retirement | Preserve evidence and plan ownership |

If only the pilot exists, use the twenty-row manifest as a clearly labeled tabletop exercise. Do not present it as a screenshot of deployed agents. The larger one-hour session can use this demonstration as its practical segment.

## Learner worksheet

Assign each group two agents. Ask them to document purpose, owner, sources, action scope, audience, evidence, decision, and next review. A decision can be retain, rename, consolidate, limit, or retire. Require a reason.

Success means each decision is traceable to evidence and an accountable person. A shorter inventory is not automatically a better outcome: two similar agents may meet different requirements.

## Backup route

Use the real administrative screenshot and recorded pilot observations if connectivity or authentication fails. Clearly label the capture date. Read the recipes and synthetic inputs locally for the comparison exercise. Do not imply that a recorded response is live or that a control succeeded when its enforcement test is pending.

## Cleanup procedure: prepared, not executed

1. Stop creation and identify only the lab rows by exact identifier and creator.
2. Preserve instructions, configuration, test results, sharing state, and owner decisions.
3. Check dependencies and access. The initial text-only recipe adds no external connection or scheduled automation, but inspect each actual agent before retirement.
4. Use the owning or administrative product surface to retire/delete the selected lab agent. Inspect the actual confirmation and recovery behavior before proceeding.
5. Verify its post-action state from administration and the maker experience. If processing takes time, record the delay and pending check.
6. Update the private inventory with the action, actor, timestamp, result, and remaining work.

Never delete by display name alone. Never bulk-delete the tenant's existing inventory as part of this lab. No cleanup has been executed in the initial pilot.

## Reflection

Which governance requirement did you establish? Which product setting supports it? What test would prove the intended outcome? Who decides when that evidence is sufficient?
